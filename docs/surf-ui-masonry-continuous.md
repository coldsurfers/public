# surf-ui Masonry — 쪽이 이어 붙고 자리를 부드럽게 잡는다

출발점: yellownmusk 피드가 쪽마다 masonry 덩이를 따로 그려, 새 쪽 위에 열마다 다른 빈칸이 남는다. 핀에 포스터 비율이 없어 추정만으로는 열이 고르지 않다.

## 결정

| # | 결정 |
| --- | --- |
| 1 | 소비처는 쪽을 이어 붙인 `items` 하나를 `Masonry` 에 넘긴다 — 쪽 경계가 없다 |
| 2 | 배치 높이는 **그려진 칸의 실측**(`ResizeObserver`, 높이 ÷ 폭)을 먼저 쓰고, 아직 안 그려진 칸만 `heightOf` 추정 — 다음 쪽은 실제로 가장 낮은 열부터 채운다. 놓인 칸은 여전히 안 옮긴다 |
| 3 | `columnCount` 가 바뀌면(화면 폭) 배치를 처음부터 다시 한다 — 늘어난 열이 비지 않게 |
| 4 | 첫 렌더 뒤에 붙은 칸은 아래에서 살짝 떠오른다(220ms · 칸마다 30ms 늦게, 최대 240ms). 첫 렌더 칸은 그대로 |
| 5 | 웹 `PinCard` 포스터는 그려질 때 아직 안 받았으면 3:4 에 잡아 두고, 받으면 원래 비율로 `aspect-ratio` 를 옮겨 간다(240ms). 이미 받은 포스터 · 서버가 그린 첫 화면은 CSS `auto 3/4` 그대로라 안 움직인다. 상태가 필요해 `'use client'` 가 된다 |
| 6 | 동작 줄이기 설정이면 4 · 5 둘 다 끈다 |
