## font family

| 키 | 쓰임 |
| --- | --- |
| `sans` | 본문 · UI. 한국어 권위 + Latin 보조(Pretendard) |
| `serif` | 헤드라인 · 매거진 마스트헤드(Instrument Serif) |
| `mono` | 메타 · 라벨 · 코드. 매거진 콜로폰 톤(JetBrains Mono) |

## font size

**rem 단일 축**입니다. 값은 전부 16px root 기준 정수 px 등가입니다. px 로 직접 적지 않는 이유는
사용자의 브라우저 기본 글자 크기 설정을 따라가야 해서입니다.

<Swatches group="fontSize" />

`3xs` · `2xs` 는 라벨 축입니다. 실측에서 9~11px 사용의 uppercase 41~68% · tracking 69~88% ·
mono 지배가 12px 위와 뚜렷하게 갈렸고, 파일당 1~2종만 쓰여 **역할이 실재**했습니다.

반면 12.5~17px 은 한 파일이 3~5종을 섞어 쓰는 드리프트라 단계를 늘리지 않고 기존 네 단계
(`xs` · `sm` · `base` · `lg`)로 접었습니다.

<Callout>
**이름에 값을 적어 넣지 않습니다.** `13` · `15` 같은 숫자 키를 거부한 이유는 하나입니다 — 토큰의
값을 바꿀 때 사용처를 전부 고쳐야 하면 간접화가 0 이라 그건 토큰이 아닙니다.
</Callout>

## letter spacing

**본문·UI 축**입니다. 세 단계뿐이고, 크기가 아니라 역할로 고릅니다.

<Swatches group="letterSpacing" />

<Preview name="letter-spacing" padded={false} />

`sprinkles({ letterSpacing })` 로 얹거나, `.css.ts` 에서 `vars.letterSpacing.normal` 을 읽습니다.
어느 쪽이든 같은 `--letter-spacing-*` 변수를 가리킵니다.

이 축이 왜 필요했는지: 아래 `editorialType` 3그룹만 `letterSpacing` 을 갖고 있어서, 본문·UI 는
브라우저 기본값(0)이었습니다. Pretendard 로 한글을 0 에 두면 글자가 느슨하게 벌어져 같은
크기에서 라틴보다 헐렁하게 읽힙니다. 그래서 소비처가 자기 CSS 로 이 자리를 메우고 있었습니다.

큰 글자는 더 조여야 같은 무게로 읽히므로 24px 이상 헤드라인은 `tight` 로 갑니다. mono 는
`none`(0) 입니다 — 고정폭 글리프는 격자가 곧 리듬이라, 조이면 코드·수치가 뭉칩니다.

<Callout tone="warning">
  **`editorialType` 의 자간과 겹쳐 쓰지 않습니다.** 저쪽은 크기까지 묶은 합성 슬롯(clamp display ·
  uppercase eyebrow)이고 이쪽은 어느 크기에든 얹는 단일 속성입니다. 합성 슬롯을 쓰는 자리에서는
  그쪽 값이 이미 자간을 정하므로 이 토큰을 덧대지 않습니다.
</Callout>

## editorial type

매거진 톤의 합성 타이포 슬롯입니다. `eyebrow` · `display` · `caption` 세 그룹이 있고,
`letterSpacing` 과 `lineHeight` 만 자기 값을 갖습니다 — 크기는 위 `fontSize` 를 읽습니다.

그 슬롯을 컴포넌트로 쓰는 쪽이 [Eyebrow](/docs/components/eyebrow) 입니다.
